# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Lean 4 + Mathlib formalization of the Tsarev and Pavlov–Sharipov–Svinolupov (PSS) integrability criteria for hydrodynamic-type systems `uₜⁱ = vⁱ(u) uₓⁱ` under strict hyperbolicity. It proves things like these: local integrability ⇔ Riemann coordinates exist and the system is semi-Hamiltonian ⇔ `H = 0 ∧ P = 0`. It also covers the classification of commuting-flow and conservation-density germs, and the generalized hodograph method in both directions.

`README.md` is written in Chinese. It is the authoritative record of what has been proved: a file-by-file results table, the precise statements, and the scope. Formula numbers follow the PSS paper (arXiv:solv-int/9407003). Lean docstrings and comments are in English.

## Commands

Lean and Mathlib are both pinned to `v4.35.0` (see `lean-toolchain`, `lake-manifest.json`).

```powershell
lake build                                   # whole library (~3000 jobs, mostly Mathlib)
lake build SemiHamiltonian.Geometry.PSSLocal # one module and its dependencies
lake env lean SemiHamiltonian/Foo/Bar.lean   # elaborate one file (its imports must already be built)
lake exe cache get                           # fetch Mathlib oleans; README lists targeted per-module fetches
```

There is no test suite in the usual sense. The checks are the Lean files in `Checks/`. They are not part of `lake build`, so run them one at a time after building:

```powershell
lake env lean Checks/Axioms.lean        # #print axioms for ~120 main theorems
lake env lean Checks/PSSExample.lean    # likewise HaantjesExample, DarbouxExample, SmoothDarbouxExample,
                                        # LocalIntegrabilityExample, ClassificationExample,
                                        # HodographExample, HodographConverseExample
```

`Checks/Axioms.lean` passes only when every theorem depends on nothing beyond `propext`, `Classical.choice` and `Quot.sound`. Any `sorryAx` or new axiom is a failure. The example files should produce no output.

On Windows, PowerShell `>` redirection writes UTF-16 files. That is why the old `.lake/*.log` files look garbled. To capture build output, use `| Out-File -Encoding utf8` or the Bash tool.

## Architecture

The work is organized in layers. Each layer instantiates or uses the one before it:

1. **Abstract differential algebra** (root files `Basic`, `Tsarev`, `Symmetry`, `Richness`, `Conservation`, plus `PSS/`).
   - `CoordinateDerivations` is a family of commuting derivations on a commutative algebra `R`.
   - `DiagonalSystem` holds the speeds and the Tsarev coefficients `coeff i j = ∂ⱼvⁱ/(vʲ−vⁱ)`. Speed gaps are `IsUnit`, not just `≠`.
   - The proofs are purely algebraic: semi-Hamiltonian ⇔ formal compatibility, and ⇔ the diagonal PSS tensor `P = 0`.
   - `PSS/` holds the frame calculus (`FrameData`), the Nijenhuis and Haantjes tensors, the diagonal `P` component formulas, and the intrinsic `K, M, Q, P` tensor recipe.
2. **`Darboux/`**: analytic existence and uniqueness for the Darboux system `∂ⱼwⁱ = Γᵢⱼ(wʲ−wⁱ)` on coordinate cubes, with arbitrary one-variable data on each axis.
   - Pipeline: radial integral equation → fixed point that is C¹ → the differential residual vanishes (this uses compatibility) → C∞ regularity by a scaling and parameter-dependence argument (`CompactSmooth`, `SmoothLinear`, `Scaling`) → the local theorems in `LocalC1` and `SmoothExistence`.
   - `Pair*` files are a parallel copy for `∂ⱼaᵢ = Aᵢⱼaᵢ + Bᵢⱼaⱼ`, used for conservation-law gradients (namespace `Darboux.Pair`). They were generated by text-transforming the base files, so they mirror the base files' structure.
   - `Curve*` files handle data given on a non-degenerate curve instead of on the axes. This is needed for the converse hodograph theorem.
3. **`Analysis/`** (mostly namespace `SemiHamiltonian.Smooth`).
   - `SmoothFunctions` instantiates the algebra with actual C∞ functions on an open `U ⊆ ι → ℝ`, as `Smooth.Functions U`. `Smooth.System` and `ofSpeeds` build diagonal systems from those functions.
   - It connects to Darboux in `TsarevLocal` (semi-Hamiltonian ⇔ `LocallyAxisSolvable` ⇔ `LocallyRich`).
   - The remaining files cover germ classifications (`Symmetry`/`Density`/`GradientClassification`, using `Filter.Germ (𝓝 p)`), conservation laws and potentials, and the hodograph method (`Hodograph`, `HodographConverse`, `HodographTransport`, `TransportUniqueness`).
4. **`Geometry/`** (namespaces `Geometry` and `Smooth`): general, non-diagonal C∞ matrix fields `M : (ι → ℝ) → (ι → ℝ) →L[ℝ] (ι → ℝ)`.
   - Supporting machinery: smooth eigenframes from the implicit function theorem, vector fields and Lie brackets, Frobenius and first integrals, coframe coordinates, and chart transport of brackets, tensors, symmetries and conservation jets.
   - The headline equivalences are in `HaantjesLocal`/`HaantjesConverse` (Haantjes = 0 ⇔ locally diagonalizable), `PSSLocal`, `Integrability` (`locallyRichMatrix_iff_*`) and `ConservationClassification` (`locallyRichConservationLaws_iff_*`).
   - Coordinates are `OpenPartialHomeomorph`s with `ContDiffOn ℝ ∞` on `source`/`target`. Everything lives on Euclidean open sets; there is no abstract manifold API.

`Checks/Axioms.lean` is a good index of the main theorem names.

## Conventions

- Every file starts with `module`, uses `public import`, and wraps its contents in `@[expose] public section`. `autoImplicit` is off.
- `SemiHamiltonian.lean` imports only the top-level result modules. A new file must be reachable through imports from it, or `lake build` will not compile it.
- When you add a headline theorem, add a `#print axioms` line to `Checks/Axioms.lean`. Also update the Chinese `README.md`: the results table, and the check count it cites (currently 120).
- Recurring options, set per file only where needed: `set_option backward.isDefEq.respectTransparency.types false` and `set_option synthInstance.maxSize 1024`.
- Sign and index conventions:
  - PDE: `uₜⁱ = vⁱ(u) uₓⁱ`.
  - `Γᵢⱼ` is used only for `i ≠ j`.
  - Conservation law: `∂ₜh = ∂ₓq`, with `dq = dh ∘ M`.
  - Hodograph: `wⁱ(u) = x + t vⁱ(u)`, with a plus sign.
  - Examples use indices `0, 1, 2`.

## Statement standards (the point of the project)

The README repeatedly stresses that results are about *actual* solutions. Keep new statements at that strength:

- Do not use `sorry`, and do not add new axioms.
- Never replace solvability with formal compatibility, and never put "solvable" inside a compatibility definition.
- Use real Fréchet derivatives (`HasFDerivAt`, `fderiv`). Smoothness means `ContDiffOn ℝ ∞` on a fixed open set; pointwise `ContDiffAt ℝ ∞` does not count as C∞ on a neighbourhood.
- Quantifier order matters. The neighbourhood or radius is chosen *before* the arbitrary initial data, jets or centralizer values, and one neighbourhood serves for all derivative orders.
- Necessity proofs must not assume Riemann coordinates or diagonalizability. They derive them.
- Out of scope for now: infinite jet algebras, higher-order vanishing and uniqueness from the paper appendices, and quasi-triviality.
